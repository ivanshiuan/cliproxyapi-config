# 踩坑庫｜Pitfalls → 每片 QA 清單

> 用法：開拍前把這份當**檢查清單**逐項套到本支片；交片前**逐項打勾**。
> 原創內容，非複製任何上游文字。分級：🔴 critical（不過不交片）／🟡 should／🟢 nice。

## A. 字幕（雙語重災區）
- 🔴 **超出安全區**：字幕不可進直式上下各 10%、左右各 5% 的危險帶（手機 UI／瀏海會擋）。
- 🔴 **CPS 過快**：閱讀速度上限 中文 ≤ ~9 字/秒、英文 ≤ ~17 字元/秒。爆了就拆句或延長停留。
- 🔴 **單行過長**：直式單行 中文 ≤ 13–15 字、英文 ≤ ~32 字元；超過就斷行（中英各一行）。
- 🔴 **時間軸重疊/間隙**：相鄰字幕不可重疊；切換間隙建議 ≥ 2 幀，避免閃爍。
- 🟡 **每段最短停留**：任何字幕 ≥ 0.8 秒，太短看不完。
- 🟡 **雙語條數不對齊**：中文與英文字幕條數應一致、時間碼對齊。
- 🟢 中英排版一致（中上英下或反之，全片統一）。
> 自動檢查：`scripts/subtitle_align_check.py`。

## B. 聲音
- 🔴 **BGM 蓋過人聲/環境聲**：有旁白時 BGM 壓到 -18 ~ -24 dB；招牌「上菜聲/油爆聲」要留出來。
- 🔴 **靜音尾巴**：成片結尾不要拖一段無聲黑畫面；偵測語音結束點後修剪。
- 🟡 **爆音/破音**：峰值控制在 -1 dBTP 以內；整體響度目標 約 -14 LUFS（社群平台常見）。
- 🟡 **音樂無縫**：BGM 比片短時要 loop + 交叉淡入，不要硬切。

## C. 畫面 / 版位
- 🔴 **版位搞錯**：直式 1080×1920（9:16）、橫式 1920×1080（16:9），開拍前鎖定，不要混。
- 🔴 **動態素材被降級成靜圖 Ken-Burns**：預告/電影感片型，動態是硬需求；引擎若無法動態合成，**先問**再決定，不要默默交靜圖。
- 🟡 **首幀無資訊**：第一幀就要有主體/主題，別用黑場開場（吃掉前 2 秒鉤子）。
- 🟢 **色調統一**：全片套同一組色彩，菜色片偏暖、提升食慾。

## D. 節奏 / 結構
- 🔴 **前 2 秒沒鉤子**：開場 2 秒內必須有衝突/利益/反差，否則直接被滑掉（見 retention-and-hooks）。
- 🟡 **鏡頭過長**：短影音單鏡頭 ≤ 2–3 秒，保持節奏。
- 🟡 **沒有 CTA**：結尾要有明確下一步（追蹤/到店/連結）。

## E. 引擎 / 流程（OpenMontage 互通）
- 🔴 **跳過 preflight**：未確認能力邊界就生成 → 中途才發現某供應商沒設定，白花成本。
- 🔴 **默默換供應商/模型/runtime**：違反成本與一致性，一律先問。
- 🟡 **沒鎖 checkpoint artifact**：每階段產出要寫入 checkpoint 且通過 schema，方便續跑。
- 🟡 **超預算才發現**：每付費階段前 `cost_tracker` 估價，對照 brief 上限。

## F. 內容安全 / 真實性（餐飲特別注意）
- 🔴 **誇大療效/不實宣稱**：食品不可宣稱療效；優惠/價格要與店內一致。
- 🟡 **肖像/商標/音樂授權**：真實素材走免費/開放來源（Archive.org/Wikimedia/Pexels）或自有；付費庫看授權條款。
- 🟢 **店資訊正確**：outro 的店名/地址/電話/營業時間逐字核對。
