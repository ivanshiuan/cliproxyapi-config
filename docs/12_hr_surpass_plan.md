# 12 — HR 軸超車計畫：把 Aibou Crew 做得好的全部拉進來，然後做得更好

> 來源：`docs/knowledge/2026-07-23-aibou-crew-competitor.md`（競品蒸餾卡）。
> 目的：逐條列出 Aibou Crew（艾柏雲端）在 HR 做得好的地方 → 對照我們現況 → 定義「比他強、更好上手、更好操作」的具體工程項目。
> 我們的不公平優勢：**LINE 通道（員工不用裝 App）+ 真損益整合（mv_daily_pnl）+ append-only audit**。

## A. Aibou Crew 做得好的完整清單（逐條蒸餾）

### A1. 排班（Scheduling）
| # | 他做得好的點 | 為什麼有效 |
|---|---|---|
| A1-1 | **一鍵排班**：系統依歷史資料建議班表，主管按一下完成 | 把「排班 2 小時」壓成 1 分鐘，是他們最大的賣點動詞 |
| A1-2 | 支援**變形工時**（二週/四週/八週）等各種班型模板 | 餐飲業幾乎都用變形工時，不支援=不能用 |
| A1-3 | **臨時改班即時生效**：員工臨時請假，主管手機上直接改，全員即時同步 | 餐飲現場最痛的就是「今天誰不來」 |
| A1-4 | 排班畫面**即時顯示人力成本佔營業額比** | 把排班從「填格子」變成「財務決策」 |
| A1-5 | 老闆設**門市人力成本 KPI**，主管排班時看得到紅綠燈 | 把總部意志下放到店長操作層 |

### A2. 打卡（Time clock）

|---|---|---|
| A2-1 | **QR code 到店打卡**：人到店掃碼才算，防「在家先打卡」 | 零硬體成本的地點驗證（貼一張 QR 就上線） |

### A3. 薪資（Payroll）
| # | 他做得好的點 | 為什麼有效 |

### A4. 法遵（勞基法防呆）— 他們最深的護城河

|---|---|---|
| A4-1 | **排班當下**就擋違規（工時上限、休息日規則、變形工時邊界），不是月底報表才發現 | 把法遵從「稽核」前移到「操作瞬間」——這是 guardrail 思維 |

## B. 對照我們現況（誠實盤點）

| Aibou 強項 | 我們現在有什麼 | 差距 |
|---|---|---|
| A1 排班 | `shifts` 表存在但**無 CRUD、無 UI、無成本預覽**（clock_router spec 明列 out-of-scope） | ❌ 全缺 — 最大洞 |
| A2-1 QR 打卡 | `ClockInRequest.source` 已保留 `"qr"` 值，但**無驗證邏輯** | 🟡 欄位在、邏輯缺 |
| A2-2 提醒 | 無；但 **LINE 通道 skeleton 已存在**（`integrations/line/`） | 🟡 管道在、訊息缺 |
| A2-3 今天誰在班 | ✅ `GET /clock/today` 已 spec（含 elapsed_hours） | ✅ 已對齊 |
| A3-1 自動分級薪資 | ✅ `labor_hours_classifier` spec：四桶 Decimal、跨午夜、國定假日、12h 上限 — **比他們可稽核**（純函式+19 條 AC） | ✅ 核心更強，但缺「×時薪→薪資單」最後一哩 |
| A3-2 員工自助查薪資/特休 | 無 | ❌ 缺 |
| A4-1 排班當下防呆 | classifier 只在 **clock-out 後**拋 `LaborLawViolationError` — 是「事後發現」不是「事前擋」 | 🟡 引擎在、時機錯 |
| A4-2 勞檢可稽核 | ✅ `audit_log` append-only（DB-level RULE）— **強過他們**（他們沒宣稱 DB 層不可竄改） | ✅ 已領先 |
| A5 導入摩擦 | 無 onboarding 流程、無定價 | ❌ 商業層待建 |

**結論**：我們的「計算心臟」（classifier）和「稽核骨架」（audit_log）比 Aibou 深；缺的是他們的**操作外殼**（排班 UI、防呆時機、員工自助、提醒）。外殼靠 LINE 補，就能同時「更好上手」（不用裝 App）又「更好操作」（老闆已經天天在用 LINE）。

## C. 超車工程項目（P0 → P2）

### P0 — 把「防呆時機」前移 + 排班補洞（打掉他們的核心賣點）

**C1. `schedule_router`（新 spec）— 排班 CRUD + 寫入時勞基法 guardrail**
- `POST /schedule/shifts`（批次建班表）、`PATCH /schedule/shifts/{id}`（臨時改班）、`GET /schedule/week`。
- **寫入當下**呼叫 classifier 的規則引擎做 dry-run：單日 >12h、七休一、變形工時邊界、月加班 46h 上限 → 違規回 422 `DomainError(labor_law_violation)`，回應附**白話原因**（「小美週三已排 10h，再加 3h 超過單日上限」）。
- 比 Aibou 好在哪：他們是提醒（可硬按過去），我們是 **DomainError + 需 override 授權 + 寫 audit_log** — 勞檢來的時候「誰在何時明知違規仍核准」有紀錄。

**C2. `schedule` 成本即時預覽（打 A1-4/A1-5）**
- `GET /schedule/cost-preview?week=`：班表 × `employees.hourly_wage` × 四桶倍率 → 預估人力成本；join 歷史同期營收 → 人力佔比。
- 比 Aibou 好在哪：他們只有「人力 ÷ 營收」；我們有 mv_daily_pnl，能給「**人力+食材+廢棄後的預估淨利**」— 排班畫面直接顯示「這樣排，週三預估淨利 $3,200」。

**C3. QR 到店打卡驗證（補 A2-1，欄位已留）**
- 店家 QR 內容 = 簽名 token（store_id + 輪換 nonce，日輪換即可）；`POST /clock/in` 帶 `source="qr"` 時驗簽 + 比對 store_id，不符回 422 `qr_store_mismatch`。
- 比 Aibou 好在哪：QR 掃碼入口直接用 **LINE 官方帳號**（掃碼→LIFF→打卡），員工**零安裝**；Aibou 要求裝 App。

### P1 — 員工自助 + 提醒（全部走 LINE，不做 App）

**C4. LINE 員工自助（打 A3-2）**
- LINE 選單：「我的班表」「我的薪資單」「特休還剩幾天」「請假」。後端只是既有 `time_clocks`/`leave_requests` 的 read view + `GET /payroll/my-slip`。
- 比 Aibou 好在哪：**不用裝 App、不用記密碼** — 台灣打工族 100% 有 LINE。「更好上手」的決定性差異。

**C5. LINE 提醒（打 A2-2/A1-3）**
- APScheduler job（`jobs/` 已有骨架）：班前 1h 提醒、應到未打卡 15min 通知店長、改班即時推播被影響員工、leave request 送店長一鍵 准/駁（LIFF）。

**C6. `payroll_close` 模組（補 A3-1 最後一哩）**
- 月結：聚合 `time_clocks` 四桶 × 倍率 × `hourly_wage` + 請假扣減 → 薪資單（Decimal 全程）；產出寫 audit_log。
- 賣點量化：「**打烊 60 秒，今天全店損益＋每人工時合法性一次看完**」— 對打 Aibou 的「30 秒算薪水」，但我們給的是整家店。

### P2 — 商業外殼（抄他們的結構）
- **C7** 國定假日表 `tw_holidays`（內政部行事曆匯入）— classifier 的 `public_holidays` 來源，順帶把「週末粗判」升級。
- **C8** Onboarding「一小時上線」腳本化：seed 精靈（店名→員工名單 CSV→LINE 綁定 QR 印出來貼牆）= 完成。
- **C9** 定價/通路研究：對錨 NT$168/人/月（人力軸同價、全域是倍數價值 vs 按門市計費）；查 TCloud 雲市集上架資格。
