## 1. 策略定位（先釘死，否則後面全是流沙）

### 1.1 三個必須先回答的問題
1. **賣給誰？** 一句話描述「最常上門、最願意回頭」的那一種人（年齡/職業/場景/預算）。
2. **為什麼選你不選隔壁？** 你的**單一**差異化錨點（口味/速度/價格/體驗/在地情感），只能挑一個當主錨。
3. **一句話定位**：`給【誰】，在【什麼場景】，提供【什麼獨特價值】的【品類】。`
   - 範例（可替換）：「給**附近上班族**，在**中午 12 點要快又要飽**的場景，提供**12 分鐘出餐、NT$180 吃飽的台式定食**。」

### 1.2 定位反模式（頂級操盤手會主動避開）
- ❌ 「什麼都賣」→ 採購雜、出餐慢、food cost 失控、客人記不住你。
- ❌ 用「比別人便宜」當唯一錨點 → 沒有護城河，被更有資本的人輾過。
- ❌ 先裝潢再想客群 → 裝潢是定位的結果，不是起點。

> **A1=SaaS 實驗室 或 兩者同等重時**：定位還要多一條——選一個**營運痛點明顯、流程可標準化**的品類，
> 因為這間店的隱藏 KPI 是「能不能把流程抽象成軟體賣給別家」。小吃/快餐/飲料因 SKU 少、流程穩，最適合當客戶零。

## 2. 選址（單店成敗 70% 在這一步）

### 2.1 加權選址計分卡（每個候選點打分，0–5，乘權重）

| 因子 | 權重 | 說明 | 點 A | 點 B |
|---|---|---|---|---|
| 目標客群密度 | 25% | 你 §1.1 那種人，走路 5 分鐘內有多少 | ⬜ | ⬜ |
| 人流量與動線 | 20% | 尖峰時段實地數人頭（早/午/晚各 30 分鐘） | ⬜ | ⬜ |
| 租金坪效 | 20% | 月租 ÷ 坪數 vs 該品類可負擔上限（見 §3） | ⬜ | ⬜ |
| 競品與互補 | 10% | 直接競品數、互補業態（帶客流）| ⬜ | ⬜ |
| 外送熱區 | 10% | 平台上該址周邊訂單密度（A11 越高越重要） | ⬜ | ⬜ |
| 可見性/招牌 | 5% | 從主要動線看不看得到 | ⬜ | ⬜ |
| 後勤條件 | 5% | 排煙/三相電/給排水/垃圾/騎樓 | ⬜ | ⬜ |
| 租約條件 | 5% | 押金、租期、漲幅、能否頂讓、有無「租金假期」 | ⬜ | ⬜ |
| **加權總分** | 100% | | ⬜ | ⬜ |

### 2.2 鐵律
- **租金占營收 ≤ 12–15%**（小吃/快餐）。用 §3 模型反推「這個租金需要多少營業額才撐得住」，撐不起直接放棄，不要愛上店面。
- 簽約前**實地數人流**三天（含一個假日），不要信房仲說的「人很多」。
- 租約務必爭取：**1–2 個月租金假期**（裝潢期不算租）、**頂讓/轉租條款**（退場活口）。

## 3. 單位經濟模型（藍圖的心臟 — 公式 + 試算）

> 全部用 §0 假設值帶入。**這就是你的 data-free 驗證**：數字撐不起來，店還沒開就該改設計。

### 3.1 投資表（CapEx，一次性）

| 項目 | 預設假設 (NT$) | 你的值 |
|---|---|---|
| 押金（2 個月租） | 120,000 | ⬜ |
| 裝潢/工程 | 600,000 | ⬜ |
| 廚房設備 | 450,000 | ⬜ |
| 家具/餐具/POS 硬體 | 180,000 | ⬜ |
| 生財器具/標誌/招牌 | 120,000 | ⬜ |
| 證照/規費/開辦雜支 | 80,000 | ⬜ |
| └ ⚠️ 若涉室內裝修/用途變更查驗 | （上項易破，抓 100,000–150,000） | ⬜ |
| 開幕行銷 | 100,000 | ⬜ |

> 鐵律：**準備好 6 個月燒錢都不賺也餓不死**的週轉金。最常見死法不是不賺錢，是**現金流斷在第 3 個月**。

### 3.2 月損益模型（P&L）

> 📐 **以下數字由 `scripts/launch_model.py` 計算並驗證——文件與工具永遠一致。**
> 改任何假設請跑 `python3 scripts/launch_model.py --turns 3.5 --ticket 220 ...`，立刻重算。

**營收驅動**
```
月營收(GMV,含稅) = 座位 × 翻桌率/日 × 客單 × 營業天數
              = 24 × 3.0 × 180 × 26   = NT$ 336,960
  內用(×0.75) = 252,720   外送(×0.25) = 84,240   日均來客 ≈ 72
```
> ⚠️ **翻桌率是頭號生死變數,隨業態差很大**【假設·可替換】：**坐下型小館 1.8–2.2 / 快餐·午餐定食 2.5–3.5 / 飲料店用「杯數/日」、雲廚用「單數/日」**。
> 本 worked example 用**快餐 3.0**(對應 §1.1「12 分鐘出餐」定位)。**對照組**:同店若只有坐下型 2.0,GMV 掉到 224,640、現金月虧 **−158,061**(更慘)。
>
> ⚠️ **客單 180 含 5% 營業稅**：真實未稅營收 ≈ 320,914。下表 COGS 以含稅 GMV 簡化估算,營業稅單獨列。

**成本結構（5 FTE × 38,000 = 人事 190,000，與 A8/A9 一致；快餐 3.0 情境）**
| 項目 | 金額 (NT$) | 占營收 % | 備註 |
|---|---|---|---|
| 食材成本 COGS | 117,936 | 35.0% | 全店統一 35%（外送 gross 入營收、抽成另列） |
| 人事（含老闆月薪 38,000） | 190,000 | 56.4% | 🚨 **真兇：5 FTE 對 34 萬營收過重** |
| 租金 | 60,000 | 17.8% | 🚨 > 15% 上限 |
| 外送平台抽成 | 26,957 | 8.0% | 外送 gross 84,240 × 32% |
| 水電/雜支 | 34,000 | 10.1% | |
| 信用卡/行動支付手續費 | 3,159 | ~0.9% | 內用刷卡 ~50% × 2.5% |
| **現金成本小計** | **432,052** | | （不含折舊、稅） |
| **── 現金損益 ──** | **−95,092** | **每月燒 9.5 萬** | 336,960 − 432,052 |
| 折舊攤提 | 29,167 | | CapEx 設備裝潢 1,750,000 ÷ 60 月 |
| 營業稅（淨額,估） | 10,430 | | (營收−食材) × 5% ÷ 1.05 |
| **── 會計損益（稅前）──** | **−134,688** | **每月帳面虧 13.5 萬** | |

> 🚨 **這個 worked example 就是最大發現**：即使是**生意不錯的快餐(翻桌 3.0、日均 72 客)**，這個成本結構仍**每月燒現金 9.5 萬、帳面虧 13.5 萬**——不是「幾乎不賺」，是**明確失血**。
> 真兇是**人事占 56%**(5 FTE 壓在 24 座小店上)，其次租金 18%。**翻桌率拉高救不了**——3.0 已經很忙還是虧。
> **要活,得動結構**：`scripts/launch_model.py` 內建的「修正可行版」(客單 220 + 翻桌 3.5 + 人事砍到 3.5 FTE + 租金 50k) → 月營收 480,480、**現金 +52,369 轉正**(但回本仍要 33 個月,偏長)。
> **重點不是任一數字,是「簽租約前就在紙上+工具裡看到生死」——這就是紙上模型的全部價值。**

### 3.3 損益兩平（Break-even，準固定成本模型）
```
台灣小吃店人事是「準固定」(月薪+排班,非隨營收浮動),故併入固定成本:
固定成本（月）≈ 租金 60,000 + 人事 190,000 + 水電雜支 34,000 = 284,000   （現金口徑）
              （會計口徑再 + 折舊 29,000 = 313,000）
變動成本率 ≈ COGS 35% + 外送平台加權 8% + 刷卡 ~1% ≈ 44%
邊際貢獻率 = 1 − 0.44 = 0.56
損益兩平月營收（現金）= 284,000 ÷ 0.56 ≈ NT$ 507,000
→ 損益兩平日營收 ≈ 507,000 ÷ 26 ≈ NT$ 19,500
→ 以客單 180 計，每日需 ≈ 108 客
```
> 對照 §3.2 預估日客量（24×2.0=48 內用 + 外送 ≈ 64 客/日），**離損益兩平的 108 客差距巨大**。
> 結論：**這組(坐下型 2.0)假設下的店不可行**，必須調整翻桌率/人事/租金（見 §3.5）。頂級團隊「先算後做」的紀律就在這。

### 3.4 回本期（Payback）
```
回本月數 = 總 CapEx(1,750,000) ÷ 月現金損益
標準假設(快餐3.0)下 → 月現金 −95,092 → 持續失血、無回本可言（先止血,別談回本）
「修正可行版」(220/3.5/3.5FTE/50k) → 月現金 +52,369 → 回本 ≈ 1,750,000 ÷ 52,369 ≈ 33 個月（偏長,理想 ≤ 30 月）
```
> 注意「現金損益」與「會計損益」兩個視角:**§11「現金流斷在第 3 月」監控的是現金損益**(含老闆要不要先不領薪);折舊不燒現金但會吃掉帳面獲利與真實回本速度。兩個都要看。


### 3.5 敏感度與槓桿（哪個旋鈕最有效）
> 由 `scripts/launch_model.py` 算出（基準 = 快餐 3.0；對「現金損益」的影響）：

| 旋鈕 | 動作 | 對月現金損益影響 | 槓桿 |
|---|---|---|---|
| 人事 | −0.5 FTE | **+19,000** | ⭐⭐⭐ 最高（接 docs/18 留任，降招募/流動成本） |
| 客單價 | +10% | +18,891 | ⭐⭐⭐ |
| 翻桌率 | +10% | +18,891 | ⭐⭐⭐ |
| Food cost | −3.5pp | +11,794 | ⭐⭐ |
| 租金 | −10% | +6,000 | ⭐（選址當下就鎖死，開店後動不了） |

> **行動結論**：最強旋鈕是**砍人事/提人效**(略勝客單與翻桌)，三者都遠勝省租金。
> 但人事不是無腦砍——砍過頭服務崩、流動率升、招募成本反噬，所以靠 **docs/18 留任引擎**用同樣的錢「留住人、減少重複招募」，比直接裁員更划算。

> **行動結論**：這型店要活，優先打**客單價 + 翻桌率**（提袋率/套餐/尖峰動線），其次把**人事**用排班與留任壓到合理；
> 租金在**選址當下**就決定生死，開店後動不了。

## 4. 菜單工程（Menu Engineering）

### 4.1 菜單矩陣（每道菜定位）
以「毛利」與「銷量」兩軸分四類，定期（月）重評：

| | 高銷量 | 低銷量 |
|---|---|---|
| **高毛利** | ⭐ 明星（主推、放菜單黃金位） | 🧩 謎題（想辦法推，搭餐/限定） |
| **低毛利** | 🐎 主力（引流、控成本、考慮微調價） | 🐶 拖油瓶（考慮下架） |

- 開幕菜單**SKU 控在 12–20**（A2 小吃型）；SKU 越少，採購/備料/出餐/training 越穩，food cost 越好控。
- 定價：`售價 = 食材成本 ÷ 目標 food cost 率`。例：成本 63 元 ÷ 0.35 ≈ **180 元**。
- 設計**至少 2 個高毛利招牌**當記憶點與利潤引擎；用套餐/加購把客單從 180 拉到 220+。

### 4.2 與軟體 OS 的接點
- 每道菜的 BOM 進 `recipes` / `recipe_lines` → 開賣即自動扣料、算**真實 food cost**（不是估的）。
- `mv_daily_pnl` 物化視圖每日給你真實毛利，菜單矩陣**用真實數據重評**，不靠感覺。

## 5. 人力與組織（最貴的隱性成本，藍圖的留任引擎）

### 5.1 依規模的組織（A8=5 FTE）
```
老闆/店長（你）── 外場/收銀 ×1.5 ── 內場/主廚 ×2 ── 兼職彈性 ×0.5
```
- 開幕期老闆**必須在現場**：你是 customer zero 的 user researcher，也是流程的第一個 debug 者。

### 5.2 招募與 onboarding（pre-launch 就要備）
- T-30 開始招募；餐飲缺工嚴重，**留任 > 招募**。
- onboarding SOP：報到日完成 → 勞健保投保、簽到、健康檢查（餐飲從業需附）、SOP 訓練、**開通員工養成遊戲化 App**（docs/18）。

### 5.3 留任引擎（接 docs/18 養成遊戲化）
- 開幕 Day-1 你只有 ~5 個員工——**先用最小子集**：一張共用表 + 每日準時發蛋 + 月底真錢加碼（NT$6,000 池）。
  **不要 Day-1 就上 7 張表 + cron job**，那是 docs/18 的「完整藍圖層」，等店穩了再上。
- 合規鐵律（呼應 docs/08 §2、docs/18 D1）：紅蛋/遊戲懲罰**只在遊戲內**，真錢只正向加碼，絕不扣薪。

### 5.4 排班合規（開店即遵守，細節見 docs/08 §2.2）
連續工作 ≤ 6 天、班距 ≥ 11 小時、月加班 ≤ 46 小時、單日 ≤ 12 小時。Phase 1 店長每週 review，Phase 2 軟體 validator。

## 6. 供應鏈與庫存

- **供應商策略**：每個關鍵食材**至少 2 家**（避免斷貨被掐）；主供應商談月結與批號（lot_no）配合（食安溯源,docs/08 §1.1）。
- **par level（安全庫存）**：每項食材設「最低庫存→自動提醒叫貨」。開幕用保守 par，跑兩週後依真實耗用（`stock_movements`）校準。
- **進貨節奏**：生鮮每日/隔日小量（保鮮、減損耗）；乾貨/包材週補。
- **減損**：報廢/試吃/員工餐都寫 `cost_events`，進真實 food cost——**不要讓「看不見的耗損」偷走毛利**（這正是本 OS 的核心價值）。

| A3 | 發票字軌/雲端發票 + 加值中心串接 | 國稅局/電子發票加值中心 | T-30 `(依賴 A2 核准)` | 接外送+雲端發票須與**加值服務中心(turnkey)簽約**取得字軌與載具歸戶；接 docs/08 §4 |

| # | 項目 | 主管機關 | 時機 | 備註 |
|---|---|---|---|---|
| B1 | 室內裝修許可（如涉及） | 地方建管 | 裝潢前 | 一定坪數/用途變更須申請，需建築師簽證 |
| B2 | 消防安全/竣工查驗 | 地方消防局 | 裝潢後、開業前 | ⚠️ **B1+B2 易因複檢/補件延誤 2–4 週**，是開幕跳票頭號風險（→ §11） |
| B3 | 招牌/廣告物許可 | 地方都發/工務 | 招牌施工前 | 尺寸/結構規範 |
| B4 | 廢棄物/油脂截留/排煙 | 地方環保局 | 裝潢**設計**階段 | 設計時就要納入後勤（§2.1），事後補很貴 |
| B5 | 騎樓/人行道/露天座位使用 | 地方道路/工務 | 擺設前 | 若擺騎樓桌椅，多數縣市須申請，常被開罰 |

**C 群 · 食安 / 人員**（開店前設立 + 營運中持續，雙態）

|---|---|---|---|---|
| C1 | 食品業者登錄「非登不可」 | 食藥署 | T-30 `(依賴 A2)` | **凡辦稅籍登記之餐飲業者一律須登錄**（無小規模豁免；免的是 HACCP 強制驗證那類，不是登錄本身）。需填統編 |
| C2 | 負責人/衛生管理人員 食安講習 | 衛福部認可單位 | 開業前 | 一定規模以上須設**專任食品安全管制人員**；小店多為負責人自上講習 |
| C3 | 從業人員健康檢查 | 衛福部/地方衛生局（執行於合格醫療院所） | 報到前 | 依 GHP：新進**體格檢查** + **每年定期複檢**（A肝/肺結核胸X光/傷寒等），結果留存備查 |
| C4 | GHP 良好衛生規範落實 | 自主 + 稽查 | 開業即 | → docs/08 §1（含禁菸標示、食品標示） |
| C5 | 勞保/健保/勞退 投保單位設立 | 勞保局/健保署 | 第一位員工到職前 | → docs/08 §2 |

| # | 項目 | 主管機關 | 時機 | 備註 |

| D1 | 公共意外責任險 | 保險公司 | 開業前 | **多數縣市對供公眾使用之餐飲場所強制投保且有最低保額**（常見每人體傷/每事故下限）——非「可選」，常是消防/營業合法性的隱含前提。務必查當地自治條例 |

## 9. 試營運與開幕行銷

- **軟開幕（T-1）**：限量、邀親友/鄰里，**唯一目的是壓測流程**（出餐速度、動線、結帳、廚房節奏），不是賺錢。蒐集回饋當晚改。
- **Google 商家檔案**：開幕前建好（地址/營業時間/菜單/照片），引導前 20 位顧客留五星評論——**本地餐飲最高 ROI 的免費流量**。
- **LINE 官方帳號**：開幕即建，加好友送小菜/折扣，沉澱會員（接 `customers.line_user_id`，docs/08 §3 個資告知必貼）。
- **外送平台上架**：若 A11>0，T-1 前完成 UberEats/foodpanda 上架與菜單/拍照（注意抽成已進 §3 模型）。
- **開幕優惠設計**：用「回訪鉤子」（首次送回訪券）而非純打折，培養回頭率而非只衝一次性人流。

## 10. 開店後 KPI 儀表板 + 軟體 OS 怎麼接

| KPI | 來源（本 OS） | 健康區間（小吃型，可替換） |
|---|---|---|
| 日營收 / 客單 / 來客 | `orders` / `mv_daily_pnl` | 日營收 → 目標 ≥ 損益兩平 ≈ 19,500（108 客，§3.3） |
| 真實 food cost % | `recipes` + `stock_movements` + `cost_events` | ≤ 35% |
| 人事成本 % | `time_clocks` + 薪資 | ≤ 30% |
| 真實淨利 % | `mv_daily_pnl` | 目標 ≥ 10% |
| 現金 variance | `cash_drawer_sessions` | ±50 內（docs/08 §5.3） |
| 員工準時率/留任 | 養成遊戲化（docs/18） | 留任 = 北極星 |
| 食材即期/報廢 | `ingredients.expiry_date` + waste 事件 | 報廢率 ↓ |

> **這就是這間店相對「一般店」的不公平優勢**：開幕第一天起，你看的是**真實損益**（扣掉招待/報廢/折讓/平台抽成後老闆口袋真的剩多少），
> 不是 POS 的「表面營收」。假設值被真實數據替換，模型越跑越準——也成為你賣給別家店的鐵證（A1=SaaS 時）。

## 11. 風險矩陣與退場條件

| 風險 | 機率 | 衝擊 | 緩解 |
|---|---|---|---|
| 現金流斷在前 3 個月 | 中 | 致命 | 6 個月週轉金（§3.1）、每週現金流盯緊 |
| 選址人流不如預期 | 中 | 高 | 計分卡 + 實地數人流；租約留退場條款 |
| Food cost 失控 | 中 | 高 | BOM 自動扣料、每日真實 food cost、SKU 精簡 |
| 缺工/高流動 | 高 | 高 | 留任遊戲化（docs/18）、排班合規、文化 |
| 食安事件 | 低 | 致命 | docs/08 §1 溯源 + §6.3 公關 SOP |
| 過度依賴外送抽成 | 中 | 中 | 養內用會員（LINE）、控外送占比 |
| 證照/消防/裝修查驗延誤致開幕跳票 | 高 | 中 | §7-B 群提前送件、預留 2–4 週緩衝、租金假期涵蓋延誤期 |

**預設退場/轉向條件（pre-commit，避免沉沒成本綁架）**：
- 連續 3 個月現金流為負且無改善趨勢 → 啟動止損（轉型菜單/砍成本/頂讓）。
- T0+6 月仍距損益兩平 >30% → 重估定位或退場。
