# 14. 店長營運 SOP — 會員成長飛輪實戰手冊

> 給**店長／店員**看的操作手冊，不是工程文件。
> 四大成長機制（儲值雙倍／裂變邀請碼／UGC 換獎／連續回訪）＋ 成效報表 ＋ 分眾推播，
> 怎麼在門市天天用、怎麼看數字、怎麼出手。
> 機制的設計理由與程式細節看 `docs/13_membership_growth_loop.md`。

---

## 0. 一頁速覽：四大機制在做什麼

| 機制 | 補的洞 | 店員要做的事 | 系統自動做的事 | 看哪個數字 |
|---|---|---|---|---|
| **儲值雙倍** | 提前收現金、沉沒成本鎖客 | 幫客人儲值、結帳時用餘額付 | 依級距加贈、推播餘額 | 滲透率、未用餘額 |
| **裂變邀請碼** | 一個客人帶一群客人 | 把客人的邀請碼給朋友用 | 綁定送點、達標雙邊發點 | 轉換率、K 因子 |
| **UGC 換獎** | 店外口碑 / Google 曝光 | 看客人貼文截圖 → 審核 | 通過發點、推播道謝 | 通過率、評論數 |
| **連續回訪** | 把單次客變習慣客 | 口頭提醒「明天再來點數加碼」 | 自動算連續天數、點數加碼 | （含在點數內） |

> 全部是**加點**或**送餘額**，沒有任何一個會扣客人的錢。發錯了都可以用新的一筆紀錄沖正（帳本只增不改）。

## 1. 每日 / 每週 / 每月例行 SOP

### 每日（開店 / 打烊）
1. **開店**：打開後台儀表板 `GET /membership/stats?days=1`，看昨天的儲值/發點/UGC 待審。
2. **營業中**：
   - 客人結帳 → 問「要不要儲值？儲 1000 送 200」。
   - 客人說朋友推薦 → 請他在抽獎/註冊頁輸入邀請碼。
   - 客人秀出 Google 評論 / IG 貼文 → 進 UGC 待審佇列幫他審核發點。
3. **打烊**：清 UGC 待審佇列（`GET /ugc/submissions?status=pending`），逐筆 approve / reject。

### 每週
- 看 `GET /membership/stats?days=7`：本週**儲值滲透率**、**裂變轉換率**、**UGC 通過率** 有沒有掉。
- 跑一次 **at_risk 分眾推播**：把快流失的常客拉回來（見 §6）。

### 每月
- 看 `GET /membership/stats`（不帶 days＝全期）：**未兌換點數負債**、**未用儲值餘額**＝帳上要認的負債，給老闆對帳。
- 看 RFM 分眾分布 `GET /membership/segments`，決定下月主打哪個分眾。

## 2. 儲值雙倍 SOP

**話術**：「我們儲值有加碼喔，儲越多送越多，餘額永久有效、沒有期限。」

**加贈級距**（系統自動算，**無條件捨去**到整數元）：

| 客人儲入 | 加贈 | 實得餘額 |
|---|---|---|
| 500–999 | 10% | 例：儲 500 → 550 |
| 1000–2999 | 20% | 例：儲 1000 → 1200 |
| 3000 以上 | 25% | 例：儲 3000 → 3750 |

**操作**：
1. 幫客人儲值 → `POST /customers/{id}/stored-value/top-up`，body `{ "amount": "1000" }`。
   系統自動寫入「儲值 +1000」「加贈 +200」兩筆，並 LINE 推播餘額。
2. 結帳用餘額付 → `POST /customers/{id}/stored-value/spend`，body `{ "amount": "450" }`。
   **餘額不足會擋下（回 409）**，不會變負數。
3. 查餘額 → `GET /customers/{id}/stored-value`；查明細 → `.../stored-value/ledger`。

> ⚠️ 法規：依台灣零售業禮券定型化契約，**儲值不可設使用期限**，不要對客人說「會過期」。

## 3. 裂變邀請碼 SOP

**話術**：「把你的專屬邀請碼給朋友，朋友首次消費，你們兩個都有回饋！」

**怎麼運作**：
1. 給老客人他的邀請碼 → `GET /customers/{id}/referral-code`（第一次叫會自動產生一組 8 碼）。
2. 朋友拿邀請碼來：在抽獎輪盤頁輸入 `ref=邀請碼`（新會員第一次轉盤時自動綁定）。
   → **朋友立刻收到 100 點註冊禮**。
3. 朋友**第一次結帳**那一刻 → **推薦人自動收到 200 點** + LINE 通知。
4. 看誰推薦了誰 → `GET /customers/{id}/referrals`。

**防弊（系統自動擋，不用擔心）**：
- 一個人**只能被推薦一次**（第二組碼無效）。
- **不能推薦自己**、**無效碼直接忽略**（不會出錯）。
- 推薦獎勵**一次性**，不會重複發。

## 4. UGC 打卡 / 評論換獎 SOP

**話術**：「在 Google 給我們五星評論、或 IG 打卡，截圖給店員，送你點數！」

**發獎金額**（依貼文類型，審核通過才發）：

| 類型 | 點數 | 為什麼 |
|---|---|---|
| Google 評論 | 100 | SEO / 搜尋曝光最值錢 |
| IG 貼文 | 80 | 擴散到朋友圈 |
| 打卡 | 50 | 輕量互動 |

**操作（人工審核，因為貼文無法自動驗證）**：
1. 客人秀貼文 → 幫他建一筆 → `POST /ugc/submissions`，body `{ "customer_id": "...", "kind": "google_review", "proof_url": "貼文連結(可選)" }`。
2. 打烊清佇列 → `GET /ugc/submissions?status=pending` 看所有待審。
3. 確認是真的貼文 →
   - 通過：`POST /ugc/submissions/{id}/approve` → **自動發點 + LINE 道謝**。
   - 不通過（截圖模糊/非本店）：`POST /ugc/submissions/{id}/reject`，body 填 `note` 原因。
4. **同一筆只能審一次**（審完再點會回 409），避免重複發點。

## 5. 連續回訪 Streak（自動，店員只要動嘴）

客人**連續多天**來消費，點數自動加碼，不用任何後台操作：

| 連續天數 | 點數倍率 |
|---|---|
| 1–2 天 | x1.0（原本） |
| 3–4 天 | x1.1 |
| 5–6 天 | x1.2 |
| 7 天以上 | x1.5 |

- 系統從訂單紀錄自動算「連續有消費的日子」，同一天來幾次算一天。
- 結帳的 LINE 收據會顯示「連續回訪 N 天 點數 xM」。
- **店員只要動嘴**：「你已經連 4 天囉，明天再來點數 1.2 倍！」

> 點數基準：每消費 100 元 1 點，再乘會員等級倍率（一般 1.0 / 銀 1.5 / 金 2.0 / 白金 3.0），最後乘連續回訪倍率。

## 6. 成效報表怎麼看（`GET /membership/stats`）

帶 `?days=N` 看近 N 天（1–365）；不帶＝全期。**流量型**數字（發點、儲值、裂變、UGC）會跟著區間走；**存量型**數字（餘額、等級分布）永遠是當下快照。

| 數字 | 意義 | 健康方向 |
|---|---|---|
| `points.outstanding_balance` | 未兌換點數＝要認的負債 | 太高要推兌換 |
| `stored_value.penetration_pct` | 多少比例會員有儲值 | **越高越好**（鎖客深度） |
| `stored_value.outstanding_balance` | 未用儲值＝預收現金 | 健康的現金流 |
| `referral.conversion_pct` | 推薦達標率 | < 50% 要檢討門檻 |
| `referral.k_factor` | 每位會員帶來幾位達標新客 | **> 0.3 開始有病毒效應** |
| `ugc.approval_pct` | UGC 通過率 | 太低代表規則沒講清楚 |

## 7. RFM 分眾 + 分眾推播（`GET /membership/segments`）

系統把每位會員依**最近來訪（R）／來訪頻率（F）／累計消費（M）**自動分成六群，一人一群：

| 分眾 | 是誰 | 該出什麼招 |
|---|---|---|
| **champion** | 最近常來、買很多 | VIP 專屬、新品先嚐、別打擾太多 |
| **loyal** | 穩定回購 | 升等進度、會員日加碼 |
| **potential** | 最近來過、還在觀察 | 第二次回訪誘因、儲值加碼 |
| **new** | 剛註冊 / 還沒消費 | 新客禮、引導第一次消費 |
| **at_risk** | 以前是好客人、最近沒來 | **想念您 9 折**、限時召回 |
| **dormant** | 久未回、價值低 | 低成本喚醒、別投太多預算 |

**分眾推播**：對某一群發 LINE →
`POST /membership/segments/at_risk/broadcast`，body `{ "message": "想念您！回來享 9 折 🎁" }`。
回傳 `audience_size`（這群有 LINE 的人數）與 `delivered`（實際投遞數）。

> 評分門檻（系統內建）：最近來訪 ≤14 天高分 / ≤45 天中分；頻率 ≥10 單高分 / ≥4 單中分；消費 ≥1 萬高分 / ≥3 千中分。

## 9. 常見問題（FAQ）

**Q：發錯點數 / 儲值怎麼辦？**
A：帳本只增不改，用一筆反向紀錄沖正即可（找工程或用後台調整），**永遠不要去改舊紀錄**。

**Q：客人說沒收到 LINE？**
A：LINE 推播是「盡力送達」，客人沒綁 LINE（只留電話/會員卡）就不會收到，不影響點數/餘額入帳。

**Q：儲值餘額會過期嗎？**
A：**不會**，法規禁止。點數才有期限（依設定）。

**Q：一個客人可以被很多人推薦嗎？**
A：不行，**一人只能被推薦一次**，系統會自動擋。

**Q：報表數字怎麼跟昨天差很多？**
A：先確認有沒有帶 `?days=N`。不帶是「全期累計」，帶了是「近 N 天」，兩者本來就不同。

要在新環境快速看到報表有數字：

```bash
make growth-demo      # 灌一份示範會員 + 儲值/裂變/UGC 紀錄，並印出儀表板
```

> ⚠️ 示範資料會寫進預設租戶，**跑測試前先 `make db-truncate`** 清掉，避免污染測試。
