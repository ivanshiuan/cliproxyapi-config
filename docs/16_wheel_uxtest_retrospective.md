## 五、發現與建議（要你拍板）

### ⚠️ 痛點 #1：沒接 LIFF，會員要手打 LINE ID（最該修）
- **現況**：圖文選單/Flex 的連結是一般 `uri`，頁面拿不到 LINE 身分，所以畫面上有個輸入框要會員填「LINE ID 或手機」。demo 用 sessionStorage 隨機生一個 U-id 頂著。
- **問題**：真實會員**不知道自己的 LINE ID**，手機板要打字，違背「掃碼即玩」。換手機/瀏覽器又變成新會員，券對不上。
- **建議**：改用 **LINE LIFF**（`liff.init` + `liff.getProfile()`）自動帶 `userId` + `displayName` → 會員**一個字都不用打**，按一下就抽。圖文選單連結改成 `https://liff.line.me/<liff-id>?campaign=…`。
- **效益**：把「1 次點擊 + 手動填欄位」變成「純 1 次點擊」，並把券真正綁定到 LINE 帳號。

### ⚠️ 風險 #1：「和牛一盤」無總量上限
- weight 8（約 9.9%/抽）且 `total_quota=None`。開幕若 2,000 抽 → 約 200 份 × 600 ＝ **NT$120,000** 失控成本。
- **建議**：給 `total_quota`（例如 30~50 份）或 `daily_quota`（每日 3~5 份），跟最大獎一樣稀有化。引擎已支援，改一個 PATCH 即可。

### ⚠️ 流程風險：壓測燒掉了真實活動的最大獎配額
- 本次測試把 `grand-open` 活動的「免單四人套餐」3 份配額抽光、awarded_count 全被灌大。
- **建議**：上線前 (a) 用 `make wheel-demo` 重新 seed 一個乾淨活動，或 (b) 重置 `awarded_count` 歸零。**正式壓測應對「拋棄式活動」做**，不要打到要上線的那一檔。
