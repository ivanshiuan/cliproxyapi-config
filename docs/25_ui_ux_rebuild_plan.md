# 25 — UI/UX 全面重製計畫（P10：目標「比 iCHEF 好用」）

> 背景：2026-07-16 Ivan 驗收判定——後端紮實，但九個畫面是「工程師介面」，
> 未達商用水準（好使用、好記憶、好操作）。P10 凍結一切新功能，唯一任務是
> 把介面重製到頂級水準。**鐵律：UI 未達標的畫面不再拿去給 Ivan 驗收。**

## 1. 先拆解 iCHEF 的介面（不是功能，是介面）

前面拆的是「功能清單」；這次拆「畫面與操作」：
- 用 browser-act/研究 agent 深扒 iCHEF interface-flow 頁、支援知識庫的
  **每一張操作截圖**：桌位圖的顏色語言、點餐畫面的左單右菜佈局、結帳流程
  的步驟數、按鈕大小與位置、字級層次。
- 同步拆 Eats365/肚肚的介面截圖作對照。
- 產出 `docs/26_interface_teardown.md`：每個畫面一節，「他們怎麼做→為什麼
  →我們怎麼做得更好」。
- **Ivan 手上若有各家 POS 的截圖/影片，直接丟進對話，優先於網路資料。**

## 2. 設計系統先行（一次定義，九個畫面共用）

- Design tokens：色彩（桌況狀態色、金額色、警示色）、字級表（平板 15" 與
  手機 6" 兩套）、間距、圓角、按鈕尺寸（油手指可按：最小 48px 觸控目標）。
- 元件庫：帳單列、菜單磁磚、狀態膠囊、數字鍵盤（結帳收現不用手機鍵盤）、
  確認彈窗、toast。
- 原則：**三秒找到、一步完成、錯了好救**（好記憶=固定位置；好操作=大目標
  少層級；好救=每個危險動作可回退且有覆核）。

## 3. 重製順序（每個畫面重做完→Playwright 全流程實測→截圖給 Ivan 過目→才算完）

1. POS 桌況＋點餐＋結帳（店員每天用 8 小時的畫面，最優先）
2. Kiosk 自助機（顧客第一眼，門面）
3. 顧客掃碼點餐/線上外帶/候位（手機三頁統一設計語言）
4. KDS/取餐看板（遠距可讀性：字級、對比）
5. 總部儀表板＋後台管理（菜單/促銷/員工管理介面化——目前只有 API 沒有管理畫面，一併補）

- Ivan 用一句話能學會的操作才算「好操作」；找不到按鈕就是設計錯，不是使用者錯。
