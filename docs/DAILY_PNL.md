# 每日真實損益（老闆今天真正賺多少）

> `GET /reports/daily-pnl` — 把一天的真實訂單、成本、人事、固定成本算成一張損益表。
> 唯讀、只有店長（admin）能看、不會寫入任何資料。決策背景見 [`DECISIONS.md`](DECISIONS.md)。

## 怎麼看

1. 瀏覽器開 `/demo/admin.html`，輸入店長通行碼登入（登入後 12 小時內有效）。
2. **同一個瀏覽器**開 `/reports/daily-pnl?format=html`（手機也可以）。預設是今天（台北時間）。

| 參數 | 說明 |
|---|---|
| `date=2026-10-27` | 營業日，預設今天 |
| `store_id=<uuid>` | 門市；系統裡只有一家啟用中的店時可省略，有多家就必須指定（回 422 並列出選項） |
| `format=html` | 人看的頁面；預設 `json`（給程式／LINE 日報用） |

## 一天怎麼算

```text
菜單價（含稅）合計
 − 折扣                      （逐張訂單用結帳台同一套折扣規則算）
 + 服務費 10%                （以折扣前總額計，結帳時另外加收）
 = 應收（含營業稅）
 − 營業稅 5%                 （內含，應收 × 5 / 105）
 = 營收（未稅）
 − 食材成本（BOM 配方）  − 報廢  − 員工餐  − 試吃  − 刷卡手續費
 = 毛利
 − 人事成本  − 固定成本（月額 ÷ 當月天數）
 = 今日估算淨利
```

- **只算「已結帳」的訂單**。還開著的、已作廢的不算，但會在「警告」欄列出張數。
- **服務費算法與 POS 結帳台逐分相同**（銀行家進位；有測試對著 #29 的 `amount_due` 驗證）。
- **人事**：時薪制 = 打卡工時 × 時薪 × 倍率（平日 1.0／加班 1.34／再加班 1.67／假日 2.0）；
  月薪制 = 月薪 ÷ 當月天數每天攤提，加班費另加。時薪、月薪都從員工表讀，不用另外設定。
- **收款對帳**：報表會把「收款單加總」跟「應收」比，差一分錢就會在警告欄標出來。

## 要你設定的東西（環境變數，前綴 `RESTO_PNL_`）

放在伺服器的 `.env.production`（本機開發放 `.env`），改完要**重啟 api 容器**才會生效。**金額只放在那裡，不要進 git。**

| 變數 | 預設 | 說明 |
|---|---|---|
| `RESTO_PNL_FIXED_COSTS_MONTHLY` | 空 | 每月固定成本，JSON，單位 NT$。**沒設的話淨利會嚴重偏高，報表會明講。** |
| `RESTO_PNL_LABOR_ON_COST_RATE` | `0` | 雇主負擔（勞保、健保、勞退）占薪資的比例，例如 `0.17`。常見約 15–20%，請會計確認。 |
| `RESTO_PNL_PRICES_INCLUDE_VAT` | `true` | 菜單價含不含營業稅。含稅（預設）= 從應收扣出 5%；`false` = 價格就是未稅營收。 |
| `RESTO_PNL_VAT_RATE` | `0.05` | 營業稅率 |

固定成本的寫法（**以下金額只是示意，不是你的數字**）：

```bash
RESTO_PNL_FIXED_COSTS_MONTHLY='{"租金": 100000, "水電": 30000, "網路電話": 2000, "其他": 5000}'
```

名稱隨你取（中英文都可以），報表會原樣列出每一項。金額是「一個月多少」，系統自動除以當月天數。
租金和水電是最基本的兩項：沒有的話報表會提醒。

**寫錯了會怎樣**：報表不會算出一個看起來正常的錯數字，而是直接回 503 並指名是哪個變數、怎麼改。
最常見的三種錯：用了全形引號 “ ”（從 LINE／備忘錄複製貼上很容易，要半形 `"`）、最後一項後面多了逗號、
把 17% 寫成 `17`（要寫 `0.17`）。金額不能是負數。

## 它「沒有」算進去的（報表都會寫在警告欄，不會假裝完整）

- 雇主負擔：沒設 `RESTO_PNL_LABOR_ON_COST_RATE` 就是 0。
- 設備與裝潢折舊、營業稅申報、營所稅。
- 沒有配方的菜單品項：成本當成 0，毛利會偏高（警告欄會寫幾個品項）。
- 服務費假設是**公司營收**（含稅）。如果實際上會分給員工，要告訴我分配方式，這是 D13。
- 外送平台抽成：目前沒有平台，所以沒有這一行。
- 服務費欄位 `orders.service_charge_rate` 來自 PR #29；在沒有 #29 的版本上服務費一律是 0，報表會警告。

- 固定成本沒有資料表（`docs/04_data_schema.md` 設計過 `fixed_cost_items`，從沒實作），所以用環境變數；
  需要分店、分期或在介面上編輯時再做成表。
- 測試：`tests/test_daily_pnl_compose.py`（純算術，期望值獨立算出）、`tests/routers/test_pnl_router.py`
  （真資料庫、真 HTTP）、`tests/test_daily_pnl_till_parity.py`（與 #29 結帳台逐分對帳，#29 合併前自動跳過）。
