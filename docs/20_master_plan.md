## 0. 一頁總覽（TL;DR）

**核心事實**：軟體(Phase 1 後端)**已實質完工**——12 router、~26 表、289 測試全綠、成長飛輪/CRM/KDS/會員/發票全閉環。
**所以瓶頸不是寫程式**,是 ① 4 個未拍板決策(D1–D4) ② 店根本還沒存在(沒選址、沒財務驗證)。

**這不是軟體專案,是「軟體已是完工資產」的開店創業案。關鍵路徑穿過你的決策與實體店,不在 codebase。**

```
 [Gate 0]      ──►   [Track A 開店籌備]   ──►   [T0 開幕]   ──►   [Track C 養成+產品化]
 決策+財務驗證        T-90 → T0 (12 週)                            開店後分兩段
 零資本·過不了不準走                                  ↑
                          [Track B 軟體上線/dogfood]──┘
                          並行·嵌在 T0 前最後 2–3 週
```

**現在唯一要做的事 = 過 Gate 0**：填 concept 假設 → 用試算器跑到「會賺」→ 拍板 D1–D4。
跑不出可行解 → 改 concept/選址/成本,**不投錢**。這道關卡可能幫你省下數百萬。

## 1. Gate 0 — 決策與財務驗證（現在 · 零資本 · 硬關卡）

> **過不了不准進 Track A。** 這是整份計畫唯一的「省大錢」槓桿。

### 1.1 要產出的決策
- 填 `docs/19 §0` 假設表:**A1 店目的 / A2 品類定位 / A3 資本上限**,以及業態翻桌率。
- 拍板 `docs/06` 的 **D1 開店日 / D2 POS 選型 / D3 員工載具 / D4 硬體採購**（D2 是 router 整合的 blocker）。

### 1.2 財務驗證（用 `scripts/launch_model.py`）
```
python3 scripts/launch_model.py --turns <你的> --ticket <你的> --fte <你的> --rent <你的>
```
迭代到出現**可行配置**：**現金損益為正 + 回本 ≤ 30 個月**。

### 1.3 關卡判定
| 結果 | 行動 |
|---|---|
| 紙上財務收斂（會賺） | ✅ GO → 進 Track A |
| 收斂不了 | 🔁 改 concept / 換更便宜店面 / 砍人事結構,**重跑**；仍不行就**不開**這個 concept |

> ⚠️ 提醒（試算器已證）：標準小店成本結構下,連快餐翻桌 3.0 都月燒 9.5 萬——**Gate 0 不是形式,是真的會擋下不可行的店。**

## 3. Track B — 軟體上線 / dogfood（並行 · 嵌在 T0 前最後 2–3 週）

`restaurant_api` 已完工,上線 = 部署 + 設定,不是重寫：
- 部署單台 VM + Docker Compose；`make seed`；POS 整合(依 **D2**)；店員訓練。
- **外部憑證要早辦**（前置長）：LINE OA 審核 30–60 天、電子發票字軌、`ANTHROPIC_API_KEY`(DevSwarm)。

### 解時序矛盾（本總綱收斂點 ①）
- `docs/06`「8 週」= **軟體交付週期**；`docs/19`「T-90 12 週」= **實體店全週期**。
- 兩者**不是兩條獨立 12 週**：軟體交付**嵌進**開店籌備的最後 2–3 週(店體在蓋、同時部署系統+訓練)。

## 4. Track C — 養成遊戲化 + 產品化（開店後 · 分兩段）

### 4.1 T0 Day-1：最小子集（不寫後端）
依 `docs/18 §5.3`：共用表 + 手動每日發蛋 + 月底真錢加碼(NT$6,000 池/帝王雞 5,000)。
**5 個員工不需要 7 張表 + cron job。** Day-1 用 Google Sheet 等級即可。

### 4.2 T0 + 1~2 月（店穩後）：實作完整後端
依賴序實作 5 份 spec（已在 `specs/`,接縫已校正一致）：
`employee_pet_models → employee_pet_service → employee_reward_service → employee_egg_settlement_job → employee_pets_router`。
工具：`router-implementer` 代理 或 DevSwarm(需 API key)；每塊 `make full-check` 全綠。
**屆時另開實作計畫,不在本總綱範圍。**

### 4.3 dogfood 驗證後：產品化
自店證明留任/損益有效 → 進既有 `docs/03` Phase 2–5（CRM → 地圖 → 連鎖 → 全 AI）→ 賣別家店。

## 6. 總資本視圖（本總綱收斂點 ③）

既有 `docs/03` 成本表**只算研發支出**(~470 萬,DevSwarm/API/雲端)。開店本身的錢**完全沒算**。

| 資本項 | 金額 (TWD) | 來源 |
|---|---|---|
| 研發(P0–P5 累計) | ~470 萬 | docs/03 §7 |
| 開店 CapEx + 6 個月週轉(單店) | ~250 萬 | docs/19 §3.1 |
| **真實總資本需求(自店+軟體)** | **~720 萬** | 合併 |

> 兩筆錢性質不同(研發是一次性平台投資、開店是單店營運),但**規劃現金流時必須一起看**——
> 別把「軟體做完了」當成「開店成本也準備好了」。
