# 選牌通 PlateGo — 業務規劃書 v0.1

> 目標：把「台灣車牌選號」從免費工具做成一門可收費的生意，
> 核心洞察是 **官方服務做得到但做得爛的地方，就是民間服務的營收點**。

---

## 1. 市場痛點（官方做不好的地方）

| # | 痛點 | 官方現況 | 我們的解法 |
|---|---|---|---|
| 1 | 想看「全台」有哪些號碼可選 | 監理服務網要一站一站查、每查一次輸一次驗證碼 | 整合查詢，一次篩遍 18+ 監理所站 |
| 2 | 不知道吉祥號何時釋出、何時開標 | 標牌公告散落各站、無通知機制 | 聚合公告 + LINE 到期/釋出提醒 |
| 3 | 競標不知道出多少才合理 | 標售紀錄可查但難用、無行情分析 | 歷史成交資料庫 → 估價服務 |
| 4 | 上班族沒空盯截標時間 | 無代理機制 | 代標代辦（成功報酬制） |
| 5 | 手機上官方網站體驗差 | 官方網頁對行動裝置不友善 | 全站 mobile-first RWD |

參考對標：car16.com 已驗證「免費整合查詢」有真實需求（媒體報導、PTT 討論），
但它停在免費工具層，**沒有把行情、通知、代標做成營收**。這是我們的切入空隙。

## 2. 產品分層

```
免費層（獲客）    ── 全國選號查詢、吉祥度評分、收藏、標牌公告、成交行情瀏覽
訂閱層（現金流）  ── 搶號通知 NT$99/月：條件訂閱 + LINE 推播（釋出、開標、截標倒數）
服務層（主營收）  ── 代標競標：得標價 10%、最低 NT$3,000，沒標到不收費
                    行情估價報告（單次 NT$500-1,000，可折抵代標服務費）
```

### 為什麼代標是對的主力

- 吉祥號標售是**價高者得的競價市場**，資訊與策略有真實價值（盯場、
  出價節奏、行情天花板判斷）。
- 成功報酬制讓客戶零風險嘗試，轉換阻力低。
- 客單價高：熱門號成交數萬～數十萬，10% 服務費單筆就是數千～數萬元。
- 有天然的口碑擴散場景（新車交車、公司車隊、車行合作）。

## 3. 延伸業務（同一批客戶、同一個 LINE 通道）

依「國人常用但官方體驗差」原則排序：

1. **車行/代辦通路版**（B2B）：車行每月固定量新車領牌，提供批次查詢
   + 代標的通路價 — 最快起量的通路。
2. **監理提醒包**：驗車到期、燃料費/牌照稅、駕照換發、強制險到期
   LINE 提醒（資料由用戶授權提供，官方只寄紙本或分散通知）。
3. **罰單查詢提醒**：定期提醒查詢 + 逾期加罰預警。
4. **車牌吉凶/數字命理報告**：台灣市場獨有的付費內容，成本近零，
   與選號流程天然結合。
5. **新車領牌代辦全包**：與代標打包成「交車禮包」賣給車行。

原則：**全部走同一個 LINE 官方帳號**，選號是獲客鉤子，
監理提醒是留存工具，代標與代辦是變現引擎。

## 4. 合規紅線（先講清楚才走得遠）

- **車牌不得單獨買賣轉讓**（號牌隨車、隨人）。所以商業模式必須是
  「以委託人名義競標的代辦 + 顧問」，絕不能碰「囤號轉賣」。
- **競標身分**：出價需委託人之監理服務網會員身分。採書面委託 +
  限定授權（指定號牌、出價上限），流程留痕，符合個資法。
  提供「教練模式」（我們給策略、客戶自己出價）作為低風險選項。
- **資料擷取**：只取公開頁面、低頻禮貌抓取、不破解驗證碼。
  中期目標是申請正式資料介接或改用政府開放資料。
- **廣告用語**：不得暗示與監理機關有官方關係；全站掛免責聲明（已做）。

## 5. 驗證路徑（先小賭再加碼）

| 階段 | 做什麼 | 驗證指標 |
|---|---|---|
| M0（現在） | 靜態站上線 + LINE 官方帳號 | 自然流量、LINE 加好友數 |
| M1 | 競標公告自動同步（無驗證碼頁優先）+ 手動代標接第一批單 | 首 5 筆代標成交 |
| M2 | 搶號通知訂閱上線（LINE Bot） | 付費訂閱 ≥ 100 人 |
| M3 | 車行 B2B 通路（3 家試點） | 月經常性代標單量 |
| M4 | 行情估價資料庫產品化 | 估價報告轉代標轉換率 |

前期成本極低：靜態站 + LINE 帳號 + 每日資料同步，一人可營運。
代標是純服務毛利，虧損風險集中在時間成本，適合先驗證再自動化。

## 6. 與本 repo 的技術銜接

- 後端如需 API/DB（訂閱條件、委託單、行情庫），直接沿用 restaurant_api
  的既有骨架模式：FastAPI + async SQLAlchemy + PG、金額用 Decimal、
  UUIDv7 主鍵、audit log append-only — 委託單與出價紀錄天然需要可稽核。
- LINE 通知複用 `restaurant_api/integrations/line/` 的統一通道設計。
- 排程抓取複用 `restaurant_api/jobs/` 的 APScheduler 模式。
